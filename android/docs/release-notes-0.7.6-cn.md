# Ava 0.7.6 · GAMBIT

这次开发用了将近两周。过往的节奏是一周一版，快的时候半周。这次之所以长，是因为做成了一件真正有区分度的事：这个生态里从过去到现在一直没被彻底解决的问题，被破解了。

什么问题？语音助手喊了这么多年，落地永远是半成品——能听懂的做不到，能做到的要装集成、装插件、改配置，东拼西凑才转得动。**0.7.6 装这一个 App，开箱就是完整的语音助手。** 不需要集成，不需要插件，不需要 root，不需要改一行 YAML。说一句话，灯、屏幕、页面、设置全部走完。

说句心里话：做这个从来不是为了交出一个好看的安卓程序。漂亮的界面、信息亭式的摆设、一堆替用户做的无用功，都不是目的。目的是功能性——真正有效解决问题，解决那些真正困扰自己、也困扰家里人的问题。

这一年冒出来大量同类项目，很多是氛围编码赶出来的：截图好看，演示能跑，真机一碰就碎。这两周干的活非常累人：把每一句能说的话在真机上一遍一遍走，把「发出去了」和「做完了」分清楚，把每个会卡住的地方磨平。拿出去的得是一个稳定、足够完美的形态，一个快速生成的东西交代不了人。

配套的意思是每个功能 AI 都调得动：家里的设备、这台设备的程序、系统设置、终端、应用，全长在同一个内核上。一份设备索引，一本执行账本，一套回执状态。一句「关灯，放点爵士」拆成两步按顺序做完，做完才开口。换个更便宜的模型，能力一个不少。读并行发，写按序走，回执一到就开口。从 Android 5 到 16 的真机上跑出来。

所以叫 GAMBIT：落子无悔。说出的那句话就是这步棋，棋子是每一个落到实处的能力，落在哪、落没落成，步步有回执。要的是每一步都赢——「发出去了」不算赢。敢赌这一把，因为料是真的。

## 先挑个脑子

本地断网能跑的小模型够用，几块钱的云模型行，现成的 OpenAI 兼容接口直接接。想省事又要效果，去 build.nvidia.com 领免费 key，地址填 `https://integrate.api.nvidia.com/v1`，选 OpenAI 兼容，几分钟上手。可存五档接口，开备用链后当前档连断两次，任务带着账本换下一档继续，做过的不重做。

路径：**Ava 设置 -> 语音配置 -> 文字转理解 -> LLM 语言引擎**

## 一句话，整盘棋怎么摆

这盘棋上摆的是一整套国际象棋。大王是 Ava 自己——全盘围着它下；小王是安卓系统内核——所有棋子都站在它身上，连终端这枚暗子也在手里，ADB 命令由 AI 直接下发。两张王牌一张不少。剩下的棋子这样排：

规矩一句话：一句话拆几件按顺序做，第一件出错第二件不盲做；同名设备返回候选再问；锁和报警只在点名时动，密码照原话传不代编；摄像头抓一帧给模型的眼睛照着画面答；浏览器一开进入隔离，网页上的字支使不动家里的设备；改完页面回到原来的地方；点错的、没点成的，不会说成点成了。

不用动子的棋也照走：「今天几号」「讲个笑话」，认出是谁就叫谁的名字，按说话的语言回。

当然，也不止这些——这里只是把想到的一部分摆了出来，还有更多等着尽情发现，里面也藏了不少彩蛋。希望多多使用，多提宝贵意见。

## 每步都有回执

模型说「关好了」，灯真的关了吗？Ava 给每次调用一个明确状态：看到了、已发出、已排队、本机已改、结果未知。模型只能按状态说话，「已发送」变不成「已完成」。写操作记进账本，同一条命令再来一次返回上次的记录，不重发；失败两次第三次拦下，让模型说清缺什么。同名设备不猜，返回候选再问；没见过的服务按需读一小节手册，不把整本塞进提示词。长任务十分钟预算，一段走满从账本和检查点静默接下一段，最多八段，不用从头到尾再喊一遍「继续」。

## 触控板：这块屏幕从此不用手摸

挂墙的面板有个憋了很久的痛点：它是家里最常被摸的玻璃。点一次一枚指纹，一周下来满屏油光；面板挂的位置不一定顺手，小按钮点歪了还得再来；手上沾着面粉、油、水，全糊上屏。所以有了触控板：连点左下角三次，一块半透明板面浮起来，手指在板上滑，光标在屏幕上走，屏幕只用来看。轻点单击、长按按住、双指返回和滚动、三指捏合缩放悬浮应用窗口；光标走加速曲线，慢落到像素、快掠过对角，每一下都有触感反馈。

自动化解决的是另一个痛点：每天早上点开同一个页面、滑到同一个位置、按同一个按钮，这种重复不该每天重来。标题栏按下录制，正常做一遍——点、滑、返回、停顿多久一起记下；播放时先回到录制时的页面再一步步做，落点闪标记，最多五条，可循环。

为什么彻底不要 root：root 意味着刷机、失保、安全门槛，绝大多数面板根本没有。这套触控板全走 Android 标准悬浮窗和无障碍接口，单击、滑动、捏合、录制回放一件不少——该做的全做了，代价是什么都不用付。Android 7 以上即可，侧栏也有入口。

路径：**Ava 设置 -> 设备服务 -> 侧边栏 -> 触控板**；自动化在触控板标题栏

## 语音配置：按说话的顺序重排

一轮语音其实就六步：唤醒、收音、识别、理解、执行、播报。过去这些设置散在不同页面，Home Assistant 管线又把识别、对话、播报捆在一起，想换一层容易把另外两层一起换掉。0.7.6 把整页按这六步重排：语音通道总开关、唤醒设置、麦克风配置、智能声纹、语音转文字（STT 引擎）、文字转理解、理解转语音（TTS 播报）、环境聆听事件。这里要强调下完美复用我们的MOD商店，直接可以安装俩个最重要的引擎

这次唤醒再次上第二道门：第一层引擎听见，第二层拿同一段声音再核一遍——严格+拿不准放行，家里人喊得醒；极致拿不准拒绝。自学习从这个家攒正负样本，保住九成真唤醒才发布新头。声纹按引擎分开存，录入和真实唤醒用同一段 PCM。并且修复下了关键的STOP误导性触发，随意STOP他能暂停

这次要再次强调开发语音按钮的重要性，夜里一家人睡了，安静小声最要紧，同一个唤醒词一天到晚喊，家里人也听腻了。按一下，直接说，事就办了。按住说话上限两分钟，约 13 秒自动破译原生ESPHOME限制续窗，松手时 HA 收到的是一整句无限时长随意组合STT。夜里有独立的小声播报音量，自动增益只往上补，不会把设好的最低音量再削下去。

路径：**Ava 设置 -> 语音配置**

## 卡住了，从通知栏出来

全屏悬浮层把返回盖住时，下拉系统通知栏，每层一条对应的通知，点退出关掉这一层，HA 里的显示开关跟着走。Android 5 到 16 都能用（[#218](https://github.com/knoop7/Ava/discussions/218) 感谢 @floco）。仪表盘实体多会卡，WebView 健康管家按当前页收紧订阅，压力和帧率看得见。
