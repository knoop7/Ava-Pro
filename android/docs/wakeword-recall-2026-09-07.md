# 成功率、误触与延迟联合检查

## 已修复

- open 和 micro 候选被拒绝后保留滑动窗口，让下一帧更新后的完整证据立即重试。上一轮清空窗口会额外等满整个窗口，可能在词尾分数下降前错过机会。接受后仍清空并进入重新就绪状态；新低分仍进入窗口，非有限分数仍拒绝。
- micro 离线确认的前 35 帧照常送入流式模型，只禁止直接确认。原来丢掉约 350 ms 输入，会在短历史截窗里切掉词头，并改变推理步长相位。
- micro 离线专用构造路径使用实际计算好的确认阈值。0.4 不再被实时模型的 0.5 下限偷偷抬高，实时阈值范围不变。
- open 严格确认先尝试 80 ms 尾窗；未确认才等待原来的 550 ms 完整尾窗。固定同一起点和阈值，只有完整窗口可最终拒绝，缺少证据仍使用原等级策略。

| 阶段 | 真候选通过 | 假候选通过 |
| --- | ---: | ---: |
| 第一阶段 | 14 | 27 |
| 原来丢弃前 35 帧的确认 | 0 | 0 |

旧零误触伴随零成功，是确认路径失灵。修复恢复了识别能力，并未让模型学会区分近音词；14/14 是条件保留率，不能宣传为全体正样本 100% 召回。正常完整历史对照中，第一阶段为真唤醒 23/31、误触 48/333，前后确认都保留这些结果。

### open 提前确认

Jarvis 第一阶段阈值 0.65、确认阈值 0.68；364 条音频中第一阶段有 28 条真候选、60 条假候选。

- 原完整窗口：确认 28 条真候选、42 条假候选。
- 80 ms 尾窗：已可确认 24 条真候选、37 条假候选。
- 提前确认加完整窗口回退：最终仍为 28 和 42，没有额外接受或丢失。
- 24/28 条成功案例可少等待 470 ms 尾部音频，不包括调度和推理耗时。

逐条验证了提前接受属于完整窗口接受集合。相同起点使早期音频成为完整输入逐样本相同的前缀；后续追加音频不会撤销原生流式评分中已存在的触发。
