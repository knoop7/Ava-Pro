# Ava 0.7.3 - BOUNCE / 弹跳

0.7.3 新增多设备唤醒-仲裁、ESPHome Noise 加密、ADB 控制总闸、WebView 分级性能调度、设置搜索、法语界面、熄屏 CPU 保活、无模型"Stop"插话检测、Home Assistant WebSocket 直连、悬浮小窗、Camera Vision Mod 与 Android 14+ Mod 加载修复，并将内置 ESPHome 基线提升到 **2026.10.1**。

## 发布后修补

0.7.3 发布后修复，已包含在当前构建：

- @wsardisson(https://github.com/knoop7/Ava/issues/200)：引导页"添加此设备"现在显示服务实际绑定的 ESPHome 端口，不再硬编码 6053。
- @wsardisson(https://github.com/knoop7/Ava/issues/201)：ESPHome 节点名不再每次服务重启追加 `_2` 后缀——重新广播前清除残留 NSD 注册，HA 里的 `voice_action` 服务不再越积越多。
- @wsardisson(https://github.com/knoop7/Ava/issues/202)：对讲入站路径不再在服务重启和权限变更后卡死，来电振铃和接听不再被静默丢弃到必须重启整机。
- @wsardisson(https://github.com/knoop7/Ava/issues/203)：通话状态机拒绝针对过期会话 ID 的接听/挂断，避免快速 hang_up/start 反复后两端状态错位；自动接听的来电现在会打断屏保并显示通话界面。

本修补版额外修复：

- 停止词模型选择：无效或过期的模型 ID 回落到内置 DSP 检测器，不再让停止检测直接失效。
- TTS 播放期间不再触发唤醒词，光标唤醒时机窗口收紧。
- 悬浮字幕遮罩不再在关闭时泄漏播放器 Surface。
- 异常 DPI 屏幕上的 Toast 不再被裁切或错位。
- 蓝牙在场 RSSI 阈值不再因信号临界波动而过触发。
- 软件更新当天已获取的发行信息指纹稳定复用。
- 悬浮窗旋转/缩放几何在屏幕方向变化后被持久化并恢复。
- 一呼百应仲裁器在多设备快速并发唤醒下不再丢失让出。
- 无 Root 设备的屏幕亮度回退不再与活动窗口遮罩冲突。
- HA 实体状态同步在关注实体变化时重放完整快照，避免重连后残留旧值。

- **设置样式**页新增手动 **界面缩放** 滑块（75%–200%，5% 步进）。缩放整体包裹 UI——密度、dp 尺寸与所有布局断点同步移动，白牌平板报告过大的 dp 宽度时不再让每个 sp/dp 都缩成蚂蚁。100% 短路到原始 Context，没动过滑块的设备渲染与今天逐位一致。当设备报告的配置超出设计范围（白牌平板常见）时，Ava 会一次性主动提醒用户调一下。同一页还能切换横屏分栏视图与主列表底部拉手。路径：**Ava 设置 -> 高级 -> 设置样式**

- **唤醒连续性**：ok_nabu 等唤醒词可以快速连续触发，一句话说完不会断开会话。连续对话模式下 TTS 播完后播一句继续提示音直接重新进入监听，复用同一 HA 会话 ID，不用再说唤醒词。唤醒预滚缓冲从唤醒触发那一刻起就缓存麦克风帧，穿过提示音和仲裁链，对着提示音说的话不会被丢掉——uplink 打开时 splice 到队列头部，HA 听到的第一帧就是你的语音而不是提示音尾巴。TTS 回声自触发保护：当助手回答的文本里包含唤醒词时按 TTS 时长暂时挂起唤醒检测，防止助手自己把自己喊醒；唤醒和停止通道分离，回答里说到停止词不会锁唤醒，说到唤醒词不会锁停止。

## 性能：把 CPU 还给设备

0.7.3 以性能为主线。唤醒词引擎、停止词识别、WebView 渲染三条最吃 CPU 的链路同时瘦身。

**唤醒词引擎**继续基于 C++ 原生流式架构，相比旧方案削减约 **86%** 算力。96 维声学嵌入在所有唤醒词之间共享，一次推理同时服务多个关键词；每个 40 ms 调度周期内的推理开销远低于实时预算。0.7.3 进一步收紧静音后的调度——确认安静后 150–250 ms 内暂停昂贵推理，空闲帧 CPU 占用降到接近零。

**停止词识别**彻底扔掉了机器学习模型——零 TFLite、零 ONNX、零推理开销、零模型加载、零 GPU/NPU 占用、零额外内存。新的原生 DSP 引擎让停止词的 CPU 占用相比旧模型方案下降接近 **100%**：旧方案每帧都要跑一次神经网络推理，新方案只在真正有声音的那几帧做轻量信号处理，空闲帧成本为零。识别精度反而更高——27 项行为测试全部通过，覆盖儿童、女性、男性、低沉沙哑四种嗓音，增益从 0.25 倍到 8 倍削波结果不变，安静房间零误触发而旧模型做不到。

**WebView 渲染**引入三档性能策略与分层调度。屏幕外卡片暂停布局绘制，被屏保遮住后逐级收紧订阅，浏览器隐藏时暂停 CSS 动画与音视频解码——每一层都可单独拿捏。在 Home Assistant 里选 `browser_power_mode` 实时换挡，不用重启。

三条链路加在一起，同一台平板可以在更低的 CPU 负载下同时跑唤醒、对讲和仪表盘——弹得轻，才能弹得高。

## 悬浮小窗：Ava Pro 自研悬浮窗技术

<img width="1216" height="638" alt="Mac_2026-08-26 17 15 07" src="https://github.com/user-attachments/assets/4c127f76-f055-430d-9296-fd17fbe21a65" />


壁挂平板是 Home Assistant 仪表盘，但它也是一台 Android 设备——查快递、回消息、开计算器、看监控、扫码，这些事不应该把仪表盘整个盖掉。0.7.3 让选中的应用以可拖动、可缩放的悬浮小窗打开，仪表盘还在底下继续刷新，小窗浮在上面，互不干扰。

Ava Pro 自研悬浮窗技术绕过了这些限制：目标应用跑在 Ava 创建的独立虚拟显示器上，画面以 H.264 硬件解码直投到悬浮的 TextureView，触摸事件通过控制通道原样转发回去——对目标应用来说它就是一块正常屏幕，对用户来说它就是一个浮在仪表盘上的真窗口。拖标题栏移动，拖右下角缩放，窗口位置和大小会被记住，下次打开还在原地。一次只开一个窗口，全局唯一，不会叠成一堆。

场景举几个例子：门口有人按门铃，仪表盘上浮出一个监控小窗确认是谁，不用切走；做饭时浮出菜谱应用，温度卡片还在旁边；孩子浮出计算器写作业，仪表盘的灯光控制不受影响；扫码签到、查快递单号、回一条消息——全都不用离开桌面。

需要 Shizuku（ADB 模式）或 Root，以及 Android 12L 及以上。条件不满足时自动回退全屏，不会卡住。在极简桌面应用选择器里给应用勾上小窗标记即可。

路径：**Ava 设置 -> 服务功能 -> 极简桌面 -> 应用选择**

## Camera Vision：一面摄像头，三种感知

0.7.3 在 Mod 商店新增 **Camera Vision**——把设备摄像头变成 Home Assistant 感知中枢。

安装后摄像头成为 HA 实时摄像头实体，可选前后镜头、帧率、分辨率和 JPEG 画质。同时跑三种端侧识别，全部默认开启，每项可单独关掉：

- **人脸检测**：BlazeFace Full Range Sparse，5 米范围，XNNPACK 加速。暴露「是否有人」「人脸数量」传感器。
- **手势识别**：BlazePalm + 21 点手部关键点，识别张开手掌和手指数量。暴露「手掌」「手势」传感器。
- **QR 扫码**：ZXing 解码，自动解析 HA tag URL 并上报 tag ID。暴露「最近 QR」「HA Tag ID」「扫码次数」传感器。

最实用的是 **屏保人像唤醒**：人脸检测接进屏保——走过来屏保消失，待着不回来，走开倒计时恢复。比内置亮度差值探测可靠得多。检测跑在独立线程，不抢捕获管线。

Camera Vision 与 Camera Stream Mod 互斥：启用时接管摄像头，Ava 自带远程摄像头自动让出。

0.7.3 同时修复了 Android 14+ 上所有带 JAR 的 Mod 无法加载的问题——系统拒绝可写 DEX/JAR，现在写入后立即只读、加载前再检查、已安装的也会自动修正。感谢 @scenix222(https://github.com/knoop7/Ava/issues/197) 完整定位原因。

## 一呼百应 Chorus Wake：同一声唤醒，只有最合适的一台回答

多台 Ava 用相同唤醒词时，不再一起争着回答。每台听见唤醒词后在局域网内进入约 **180 ms** 本地仲裁，综合唤醒置信度与增益前真实声压，让听得最清楚、通常也是最近的设备接手会话。得分接近时稳定轮换，不会永远偏爱某一台。

让出的 Ava 保持在线，用暗场和呼吸三点光表示已交出回答。获胜设备在回答、停止或超时时发送三次结束确认，其他设备平滑恢复；即使一个包丢失，90 秒保险也不会让它们永久沉默。

仲裁包不传麦克风录音，只交换设备身份、唤醒身份、时间与压缩得分。真实声压权重高于模型置信度，避免远处高灵敏麦克风总是抢走会话。仲裁器无法工作时本机直接回退正常唤醒。不需要云端、MQTT 或额外自动化。

一呼百应默认开启。只有一台 Ava 或在意省去 180 ms 仲裁窗口时可关闭。

路径：**Ava 设置 -> 语音配置 -> 一呼百应**

## ESPHome Noise：语音卫星也可以加密

<img width="780" height="460" alt="Mac_2026-08-26 17 27 04" src="https://github.com/user-attachments/assets/b72fe21c-a472-40c3-b68a-79c8cbfb5580" />


内置 ESPHome 协议与固件基线提升到 **2026.10.1**。ESPHome API 现在支持标准 **Noise NNpsk0** 加密握手：设备生成 32 字节 Base64 密钥，与 HA 中该设备使用同一密钥。连接先完成 X25519 协商与预共享密钥验证，随后语音、实体、蓝牙代理与服务调用进入 ChaCha20-Poly1305 保护的通道。

密钥留空时保持明文兼容。Ava 仅在用户显式配置密钥后才广播 Noise 支持并要求加密。

路径：**Ava 设置 -> 连接 -> ESPHome -> API 加密密钥**

## 外部控制终于有了总闸门

ADB 与本机广播过去可以直接唤醒 Ava、静音麦克风、启停服务、授予权限或重载 Mod。0.7.3 为整条入站控制链增加独立总开关。关闭 **ADB 总控** 后这些广播都会被忽略；HA 自己的麦克风与唤醒实体仍按原信任边界工作。

路径：**Ava 设置 -> 高级 -> Android 意图执行 -> ADB 总控**

## WebView 性能切换：每一层都可以自己决定

同一台平板，白天是可视对讲屏，晚上是床头牌，周末是全屏仪表盘。0.7.3 让浏览器先选一档总体节奏，再逐层细调。

- **高性能**：摄像头和实时页面保持连续更新，每一帧到位。适合可视对讲、实时监控。
- **自适应**：你在看时全速刷新，离开后自动收紧。日常 HA 仪表盘用这档最舒服。
- **省电**：面向没有实时视频的状态页，更早休息并暂停绘制，触摸立即恢复。床头牌、门口屏用这档最省。

三档都可在 HA 里直接切换——`browser_power_mode` 是下拉实体，选完即生效，不用重启 Ava。自动化里一句 `select_option` 就能按时间或场景换挡。

路径：**Ava 设置 -> 屏幕与浏览器 -> 浏览器设置**

## 回声参考总线重做：通话与语音不再互相抢声音

软件回声消除改用带引用计数的共享远端总线。语音卫星与局域网通话可同时持有播放参考；暂停一条不会让另一条的 AEC 失去参考。多条播放路径重叠时改用浮点混音，只在最终读取时留余量，不再每个写入者提前削平。这修正了语音、音乐与通话重叠时自适应滤波器学不动的回声失真。

## 一声 Stop，全场安静

<img width="500" height="646" alt="Mac_2026-08-26 17 29 56" src="https://github.com/user-attachments/assets/8f89cdc5-648b-4986-b440-6474b1d911f8" />


闹钟正响，或助手正说到一半——你只需要说一声"Stop"。一声就够。

0.7.3 彻底重写了停止词识别，**全程没有使用任何机器学习模型**。旧方案依赖微型分类模型，在安静房间里会自己跳起来；新引擎扔掉模型，改用完全基于信号本身的判别方法，在安静房间里一声不吭，却在你真正开口那一瞬精准接住。

27 项行为测试全部通过：孤立"Stop"在不同音量下被准确识别，长嘶嘶声、孤立元音、连续讲话被正确拒绝；儿童、女性、男性、低沉沙哑四种嗓音都能接住，快速含混和拖长音的"Stooop"也接得住；真实设备上的房间尾音、声门脉冲间断、慢速 /t/ 闭塞逐一修复；TTS 残响叠加下用户开口仍被接住，而 TTS 残响自己永不假触发。增益从 0.25 倍到 8 倍削波，识别结果不变。

它分得清"Stop"和环境噪声，分得清你的声音和 Ava 自己正在播的声音，也分得清一次打断和连续重复的喊声。闹钟、连续对话、助手回答三种场景全面支持，自动生效。唤醒阶段安静待命，等进入对话或闹钟后才上岗。

停止词现在可以在语音配置里自行选择：默认是内置的原生 DSP"Stop"（无模型、无灵敏度调节）；也可以换成当前唤醒引擎下的任意模型作为停止词并调节灵敏度；不需要时可以完全关闭。

路径：**Ava 设置 -> 语音配置 -> 停止词**

## 熄屏时保持 CPU 唤醒：连接不再被深度睡眠吞掉

电池平板熄屏后，厂商省电策略常把 CPU 推进深度睡眠。保活心跳、Wi-Fi 续期都依赖一个还醒着的 CPU——CPU 睡死，续期也跟着睡死，连接就断了。

0.7.3 在「后台保活」页新增 **熄屏时保持 CPU 唤醒** 开关。开启后屏幕关闭期间 Ava 阻止深度休眠，保持 HA 连接不断；屏幕点亮立即恢复正常。进程意外退出时系统自动收回。默认开启，面向需要熄屏常驻的电池平板。常电设备或不需要熄屏保活的可以关掉省一点电。

路径：**Ava 设置 -> 服务功能 -> 后台保活 -> 熄屏时保持 CPU 唤醒**

## 设置终于可以直接搜索

## Home Assistant WebSocket 直连：状态、操作、摄像头都走最近的路

0.7.3 完成 Home Assistant 直连。过去实体状态要等 HA 反向连回 Ava 的 ESPHome API 才能到达；现在 **状态走 WS 实时推送**，直接从 HA WebSocket 流过来，不可用时回落 ESPHome 通道。新关注的实体一旦被订阅，会话在兴趣变化时重启并重放完整快照，新实体立刻有值。

**操作走 WS 直达** 让快捷实体、媒体和场景经 WebSocket 直接调用，不再排队等 ESPHome 连回来。**登录后拉摄像头和封面** 让快捷实体摄像头和媒体封面用 HA 登录令牌访问，不再只靠 ESPHome 地址拼 IP。

关闭 Ava 蓝牙总开关后，HA 可能仍保留由这台 Ava 发现的远程蓝牙设备。0.7.3 可手动或自动清理这些残留，只删除明确标记为通过它接入的 Bluetooth 配置，不触碰 ESPHome 设备本身和其他代理共享的设备。

路径：**Ava 设置 -> 连接 -> Home Assistant -> 核心 / 更多**
